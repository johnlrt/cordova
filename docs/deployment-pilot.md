# Cordova: пилот на одном хосте

Условия пользователя от 2026-10-09 (Asia/Baku). Документ уточняет ближайшую схему размещения исходного roadmap; форматы API, протокол ноды и требования к корректности сохраняются, пока отдельная задача их не изменит.

## Роли компьютеров

| Компьютер | Роль в пилоте |
| --- | --- |
| Хост друга `truekant`: Ultra 5 125, Intel graphics и NPU, 64 ГБ DDR5 | Go-шлюз, распределение запросов, одна локальная Rust-нода и runner модели |
| Ноутбук пользователя: i7-12700H, 16 ГБ RAM, RTX 3050 4 ГБ | Обычный клиент API/будущего интерфейса; модель на нём для этого пилота не запускается |
| MacBook друга | Недоступен, пилот от него не зависит |

Путь запроса после реализации: клиент i7 → шлюз на Ultra → единственная локальная нода на Ultra → llama.cpp → ответ клиенту. Нода и её runner — отдельные процессы на одном компьютере со шлюзом. Размещение на одном хосте не отменяет их разделение в архитектуре.

## Один канал

Канал в этом пилоте означает один слот одновременно выполняемой генерации, а не аппаратный канал памяти. Исполнитель один, слот один; динамическое увеличение количества каналов пока не требуется. Объём 64 ГБ RAM не определяет число слотов или скорость генерации.

Текущий mock-шлюз допускает один chat-запрос за раз. При занятом слоте второй запрос получает HTTP 429 `rate_limited` и `Retry-After: 2`. После завершения или ошибки слот освобождается. Проверка здоровья и каталог моделей доступны независимо от занятости. Очередь ожидания пока не реализована.

## Что готово и что дальше

Готов только Go API с mock-исполнителем и лимитом одного запроса. Реальная локальная нода, модель, серверная токенизация и сетевой доступ клиента ещё не готовы. В mock-ответах остаются синтетические счётчики и маркировка mock.

Следующие небольшие этапы:

1. На хосте друга зафиксировать точную ОС, runner и модель, проверить происхождение артефакта, токенизацию, реальную память и время генерации при одном слоте. Стартовая модель из roadmap — Qwen2.5-1.5B-Instruct Q4_K_M; более крупная модель допускается только после измерений и отдельного решения.
2. Подключить Rust-ноду и runner на том же хосте к Go-шлюзу, реализовать отмену и освобождение единственного слота.
3. Настроить доступ с клиентского i7 и проверить полный путь запроса. Текущий адрес `127.0.0.1:8080` доступен только на самом хосте.

Intel GPU и NPU не проверены этим проектом. Не обещать их использование и не называть их память дополнительной RAM/VRAM без фактических данных. Проверку CPU-исполнения можно проводить отдельно от проверки ускорителей. Тест на локальной RTX машины разработчика не заменяет проверку Ultra.

## Обновление исходников на сервере

Из корня checkout с установленным Go, после остановки старого процесса:

```powershell
git pull --ff-only
./scripts/start.ps1 -Rebuild
```

Обычный `start.ps1` сохраняет возможность запускать готовый бинарник без Go. Поэтому без `-Rebuild` старый бинарник может сохранять прежний лимит. Первый Windows bundle не обновляется автоматически вместе с исходниками. `.local/api-key.txt` при пересборке сохраняется.
