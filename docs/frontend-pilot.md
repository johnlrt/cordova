# Первый интерфейс Cordova

Это frontend пилота Cordova: Svelte 5, SvelteKit 2, TypeScript strict, статическая сборка. Главный экран `/` объясняет продукт и показывает точное предупреждение о приватности; интерфейс первоначального mock-пилота доступен на `/pilot` с разделами `#overview`, `#nodes`, `#models`, `#docs`.

## Аккаунтный M1 frontend

`/login`, `/register`, `/recover` и закрытая оболочка `/dashboard` реализуют пользовательские сценарии F1. Вход поддерживает необязательный TOTP, восстановление требует одноразовый recovery code и показывает 24-часовую блокировку выплат. Регистрация передаёт версию `privacy-v1`; после ответа сервера recovery-коды показываются один раз и остаются только в памяти страницы до явного подтверждения сохранения. `returnTo` принимает только локальный путь.

`/dashboard/keys` загружает owner-only список API-ключей, создаёт ключи с выбранными разрешениями, моделью и дневным лимитом XMR, отзывает ключи с подтверждением и повторно читает состояние сервера после мутации. Лимит переводится в piconero целыми десятичными строками без `Number` для дробной части. Создание требует отдельного подтверждения уведомления о приватности и CSRF-токена. Новый секрет показывается только один раз; его можно скопировать только по нажатию либо выделить вручную. Закрытие блока, переход со страницы и завершение сессии очищают секрет из состояния интерфейса. Список содержит префикс, права, модели, лимит, последнее использование и состояние; полные секреты и verifier не возвращаются.

Аккаунтный клиент использует same-origin cookie credentials, `no-store`, CSRF для авторизованных POST, безопасные типизированные ошибки и отменяемые чтения. Dashboard загружает только метаданные `/api/usage`; он не читает и не показывает текст запросов. C4 WebSocket получает одноразовый ticket через POST, отправляет его первым кадром, проверяет envelope, порядок sequence, account binding, дубликаты и ревизии. Live-событие приводит к повторному REST-запросу; при потере сокета включается 30-секундный опрос, при скрытии вкладки соединение останавливается. Сессия, кэш истории и курсор не сохраняются в `localStorage`.

В режиме M1 Go gateway реализует регистрацию, вход, восстановление, сессии, историю usage и C4 live-канал. HTTPS nginx отдаёт собранный frontend и проксирует account/API/WebSocket-запросы в шлюз. Быстрый `scripts/start.ps1` запускает отдельный Stage 1 mock API и не поднимает аккаунты; для настоящего M1-пути нужен Compose-стек из `infra/`.

Интерфейс открывается на английском. Переключатель `EN` / `RU` в верхней панели меняет язык всех четырёх разделов, сообщений об ошибках и окна подключения; выбор сохраняется в `localStorage` под ключом `cordova-language`.

Визуальная система сохраняет тёмную палитру Cordova и использует системный шрифт устройства, более чёткую иерархию текста, единые карточки и увеличенные кнопки. Стиль остаётся одинаковым при смене языка. Навигация и ключевые действия показывают понятные состояния загрузки, ошибки и восстановления.

## Что показывается

- Обзор: реальная доступность mock-шлюза и длительность health-запроса. График содержит до 12 измерений текущей сессии, без выдуманной истории. Это не скорость генерации.
- Нода: конфигурация truekant — Ultra 5 125, 64 ГБ RAM, один слот. Эти данные заданы командой; автоматического определения RAM, использования GPU/NPU, состояния runner или занятости слота нет.
- Каталог: `GET /v1/models` с существующим Bearer-ключом. Текущий `cordova-chat-small-v1` — синтетический исполнитель, а не установленная AI-модель.
- Документация: работающие endpoint-ы, подключение ключа и ограничения пилота. Health обновляется раз в 20 секунд на видимой вкладке; каталог — после подключения и ручного обновления.

Интерфейс сохраняет явную маркировку MOCK в пилотном разделе. Нет чата, управления нодами, денежных операций или заявлений об измеренной мощности. Account API для сессий, истории, live-обновлений и ключей подключён к dashboard; список нод и настоящая генерация ещё не интегрированы.

## Запуск вместе со шлюзом: Windows

Нужны Node.js 24.x и Go 1.27.2. Из корня репозитория, после остановки старого сервера:

```powershell
Set-Location frontend
npm.cmd ci
npm.cmd run build
Set-Location ..
./scripts/start.ps1 -Rebuild
```

Откройте `http://127.0.0.1:8080/`. Скрипт обнаружит `frontend/build/index.html`; gateway раздаёт только каталог сборки и сохраняет маршруты API. Пересборка gateway обязательна после обновления Go: старый release-бинарник ещё не знает `-web-dir`. `frontend/build/` и `node_modules/` не коммитятся.

Нажмите «Подключить шлюз» и введите ключ из `.local/api-key.txt`. Он остаётся только в памяти страницы и очищается при отключении или перезагрузке. Не вставляйте ключ в URL, Git, Issues или скриншоты. Подключение здесь — проверка Bearer-ключа, не вход в аккаунт.

## Разработка

В первом терминале из корня запустите `./scripts/start.ps1 -Rebuild`. Во втором:

```powershell
Set-Location frontend
npm.cmd ci
npm.cmd run dev
```

Откройте `http://127.0.0.1:5173`. Vite проксирует `/healthz`, `/v1` и `/api` на `http://127.0.0.1:8080`, поэтому браузер использует один origin. Если gateway запущен на другом локальном порту, задайте адрес перед запуском Vite:

```powershell
$env:CORDOVA_API_TARGET = 'http://127.0.0.1:8082'
npm.cmd run dev
```

Не подставляйте чужой адрес: прокси передаёт ему Bearer-ключ. Адрес шлюза на Ultra для клиентского i7 станет доступен после отдельной настройки сети. `127.0.0.1` на i7 не ведёт к компьютеру друга. Публичного HTTPS-демо сейчас нет.

Linux: используйте `npm` вместо `npm.cmd`. После обновления Go пересоберите бинарник: `(cd server && go build -trimpath -o ../bin/cordova-gateway ./cmd/gateway)`, затем `sh scripts/start.sh`. Скрипт автоматически подключает собранный интерфейс. Ручной gateway принимает `-web-dir frontend/build` из корня проекта.

## Проверки

```powershell
Set-Location frontend
npx.cmd playwright install chromium
npm.cmd run check
npm.cmd run check:browser
npm.cmd run test:unit
npm.cmd run test:browser
npm.cmd run build
```

`npm.cmd run check`, `npm.cmd run check:browser`, `npm.cmd run test:unit`, `npm.cmd run test:browser` и `npm.cmd run build` проверяют типы, DTO/auth/live границы, пять Chromium-сценариев на тестовых REST/WebSocket fixtures и статическую сборку. Для браузерной проверки через реальную M1-связку поднимите Compose-стек (`make bootstrap-dev`, `make config-check`, `make up`), затем в PowerShell выполните:

```powershell
$env:CORDOVA_M1_ORIGIN = 'https://localhost:8443'
npm.cmd run test:m1
```

Сценарий регистрирует одноразовые локальные аккаунты, отправляет запрос в синтетическую WSS-ноду и проверяет, что dashboard обновился через live-инвалидацию и REST, а другой аккаунт не видит его историю. `make smoke` и `make test-edge` дополнительно проверяют mock inference, usage projection, nginx TLS/deep links и C4 WebSocket. Все эти проверки входят в GitHub Actions; локальная проверка Compose требует Docker Desktop/Compose и OpenSSL. Inference остаётся синтетическим, тестовые кредиты нулевые; проверка на железе truekant не заявляется.
