# Первый интерфейс Cordova

Это небольшой завершённый frontend-этап. Svelte 5, SvelteKit 2, TypeScript strict, статическая сборка. Четыре раздела одной страницы: `#overview`, `#nodes`, `#models`, `#docs`. Аккаунтные маршруты из исходного roadmap ещё не реализованы.

Интерфейс открывается на английском. Переключатель `EN` / `RU` в верхней панели меняет язык всех четырёх разделов, сообщений об ошибках и окна подключения; выбор сохраняется в `localStorage` под ключом `cordova-language`.

## Что показывается

- Обзор: реальная доступность mock-шлюза и длительность health-запроса. График содержит до 12 измерений текущей сессии, без выдуманной истории. Это не скорость генерации.
- Нода: конфигурация truekant — Ultra 5 125, 64 ГБ RAM, один слот. Эти данные заданы командой; автоматического определения RAM, использования GPU/NPU, состояния runner или занятости слота нет.
- Каталог: `GET /v1/models` с существующим Bearer-ключом. Текущий `cordova-chat-small-v1` — синтетический исполнитель, а не установленная AI-модель.
- Документация: работающие endpoint-ы, подключение ключа и ограничения пилота. Health обновляется раз в 20 секунд на видимой вкладке; каталог — после подключения и ручного обновления.

Интерфейс сохраняет явную маркировку MOCK. Нет чата, регистрации, управления аккаунтными ключами, денег или заявлений об измеренной мощности. API-клиент проверяет существующий контракт первого этапа; будущий account API потребует отдельной интеграции.

## Запуск вместе со шлюзом: Windows

Нужны Node.js 24.x и Go 1.27.2. Из корня репозитория, после остановки старого сервера:

```powershell
Set-Location frontend
npm.cmd ci
npm.cmd run build
Set-Location ..
./scripts/start.ps1 -Rebuild
```

Откройте `http://127.0.0.1:8080/`. Скрипт обнаружит `frontend/build/index.html`; gateway раздаёт только каталог сборки и сохраняет маршруты API. Пересборка gateway обязательна после обновления Go: старый release-бинарник ещё не знает `-web-dir`. `frontend/build/` и `node_modules/` не коммитятся.

Нажмите «Подключить шлюз» и введите ключ из `.local/api-key.txt`. Он остаётся только в памяти страницы и очищается при отключении или перезагрузке. Не вставляйте ключ в URL, Git, Issues или скриншоты. Подключение здесь — проверка Bearer-ключа, не вход в аккаунт.

## Разработка

В первом терминале из корня запустите `./scripts/start.ps1 -Rebuild`. Во втором:

```powershell
Set-Location frontend
npm.cmd ci
npm.cmd run dev
```

Откройте `http://127.0.0.1:5173`. Vite проксирует `/healthz` и `/v1` на `http://127.0.0.1:8080`, поэтому браузер использует один origin. Если gateway запущен на другом локальном порту, задайте адрес перед запуском Vite:

```powershell
$env:CORDOVA_API_TARGET = 'http://127.0.0.1:8082'
npm.cmd run dev
```

Не подставляйте чужой адрес: прокси передаёт ему Bearer-ключ. Адрес шлюза на Ultra для клиентского i7 станет доступен после отдельной настройки сети. `127.0.0.1` на i7 не ведёт к компьютеру друга. Публичного HTTPS-демо сейчас нет.

Linux: используйте `npm` вместо `npm.cmd`. После обновления Go пересоберите бинарник: `(cd server && go build -trimpath -o ../bin/cordova-gateway ./cmd/gateway)`, затем `sh scripts/start.sh`. Скрипт автоматически подключает собранный интерфейс. Ручной gateway принимает `-web-dir frontend/build` из корня проекта.

## Проверки

```powershell
Set-Location frontend
npm.cmd run check
npm.cmd test
npm.cmd run build
```

Тесты проверяют декодирование API и безопасные сообщения об ошибках. Go-тесты дополнительно проверяют static UI, отсутствие листинга каталогов, сохранение авторизации API и недоступность файлов вне сборки. В браузере проверены обзор, каталог с корректным и неверным синтетическими ключами, очистка ключа после reload, навигация и узкий экран. Проверки на реальном Ultra, ускорители и inference в этот frontend-этап не входят.
